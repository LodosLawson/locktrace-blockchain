account_tree Protocol Architecture & 1 Trillion Fixed Supply Tokenomics

LockTrace adopts a Hybrid PoW (Proof of Work) v2 + Active Quorum Peer-Validator consensus model rather than centralized validator cartels. The ledger state is managed via SQLite WAL with JSON block persistence.

1. Fixed Supply & Treasury Vault

The total maximum supply is mathematically capped at 1,000,000,000,000.00000000 BCT. New wallet welcome bonuses (1.00 BCT) and mining subsidies (0.05 BCT) are disbursed directly from the Genesis Treasury Vault (BCT_HAZINE_...). Future inflation or token minting is strictly impossible.

2. 1% Transfer Fee Distribution

A 1% network fee applies to all standard transfers. 50% returns to the Treasury Vault to preserve circulating supply scarcity, while the remaining 50% is distributed to the block proposer and active Quorum validators.

3. 70% / 30% Hybrid Block Reward

For each sealed block, 70% of the total reward pool goes to the PoW proposer who solved the cryptographic challenge, and 30% is split equally among active P2P validating nodes (Quorum Pool).

4. 10^8 Atomic Units (Zero Drift)

To prevent IEEE-754 floating point rounding drift at a 1-Trillion scale, all balance and fee computations are executed in 10^8 atomic integer units (1 BCT = 100,000,000 units).

enhanced_encryption Cryptographic Security & Signed Release Integrity

LockTrace mathematically guarantees user asset sovereignty and source code integrity through cryptographic proofs.

1. SECP256k1 & Deterministic Low-S

Employs the same battle-tested elliptic curve as Bitcoin and Ethereum. RFC 6979 deterministic HMAC-SHA256 k-generation and mandatory canonical Low-S signatures prevent signature malleability attacks.

2. Binary Merkle Tree & SPV Proofs

Transactions in every block are structured into a binary SHA-256 Merkle tree. Light clients (web browsers) mathematically verify transaction inclusion using O(log N) Merkle audit paths without downloading the full chain.

3. AES-256-GCM PIN Vault

When encrypting your wallet with a PIN, private keys are protected client-side via WebCrypto PBKDF2 (100,000 iterations), random 16-byte salt, and 12-byte IV using AES-256-GCM. Unencrypted keys are never saved to disk.

4. SHA-256 Release Seal & IPFS CID

The official web interface SHA-256 digest and IPFS CIDv1 address are signed by the Release Authority public key and sealed on-chain. If any client file is tampered with, the node enforces an immediate lockout.

3. Hybrid Consensus, Difficulty Scaling & Deflationary Mechanics

Dynamic PoW Scaling • BFT Validator Quorum • 1% Protocol Fee Split

The LockTrace Layer-1 network combines cryptographic Proof-of-Work (PoW) with Byzantine Fault Tolerant (BFT) multi-validator quorum confirmation:

  • Dynamic Difficulty Scaling: The target SHA-256 mining difficulty scales adaptively from 3 to 4 as soon as 8 or more miners join the active peer pool, maintaining optimal block times and resisting 51% hashrate spikes.
  • BFT Validator Quorum: Blocks require both a valid PoW nonce solution and cryptographic multi-signature approval from the active validator committee before permanent blockchain inclusion.
  • 1% Protocol Fee Split & Deflation: Out of the automated 1% transaction fee, 50% is permanently locked into the Treasury Vault (reducing circulating supply over time), while the remaining 50% is split 70% to the block proposer and 30% to the validator quorum.
  • Sequential Nonce Enforcement: Every transaction enforces an integer account nonce to strictly prevent replay attacks and double-spending attempts.

4. Cryptographic Frontend Seal & Anti-Phishing Defense

On-Chain Code Sealing • SHA-256 • ECDSA Release Authority

A critical vulnerability of Web3 dApps is DNS hijacking, CDN injection, or unauthorized code tampering (XSS / supply-chain attacks). LockTrace addresses this at the blockchain consensus layer:

  • On-Chain Code Sealing: Every frontend release (index.html and sw.js) is hashed via SHA-256, cryptographically signed by the official Release Authority (BCT885bc...), and anchored permanently on-chain in a release block.
  • Node-Level Security Lockout: All network nodes independently verify the SHA-256 checksum and ECDSA signature prior to serving the web interface. If a single byte is altered, an automatic HTTP 403 Security Lockout is triggered, safeguarding user funds.
